Nota sobre entorno de pruebas: Los tests de integración que validan rutas autenticadas (app-auth, app-events, app-profile, app-chat, app-saved, app-admin) requieren variables de entorno TEST_USER_EMAIL, TEST_USER_PASSWORD, TEST_ADMIN_EMAIL y TEST_ADMIN_PASSWORD configuradas. Sin estas variables, los tests de autenticación se omiten automáticamente (it.skip) para no bloquear el pipeline. Los tests de app-places funcionan sin credenciales de usuario.

Framework: Jest 30.4.2 + Supertest 7.2.2 + TypeScript
Estrategia: Pruebas de integración HTTP end-to-end contra la app Express real (sin mocks de base de datos)
Ejecución: npm test desde la raíz (Turborepo ejecuta Jest en paralelo en todos los servicios)

4. Ejemplos de Pruebas Realizadas

4.1 Prueba que pasó — Validación de inputs (app-places)

// Resultado: PASS — No requiere credenciales de Supabase
describe('POST /places/search-nearby', () => {
  it('rechaza si falta location', async () => {
    const res = await request(app)
      .post('/places/search-nearby')
      .send({ radius: 500, type: 'restaurant' })
    expect(res.status).toBe(400)  // ✓ Retornó 400
  })

  it('llama a Google Maps y retorna places para coordenadas válidas', async () => {
    const res = await request(app)
      .post('/places/search-nearby')
      .send({ location: { lat: -33.4364, lng: -70.6358 }, radius: 500, type: 'restaurant' })
    expect([200, 500]).toContain(res.status)   // ✓ Retornó 200
    if (res.status === 200) {
      expect(Array.isArray(res.body.places)).toBe(true)  // ✓ Array de lugares
    }
  }, 15_000)
})

4.2 Prueba condicional — Autenticación (app-auth)

// Usa it.skip automáticamente si no hay TEST_USER_EMAIL en .env
const hasAuthTestUser = Boolean(TEST_USER_EMAIL && TEST_USER_PASSWORD)
const itIfAuthUser = hasAuthTestUser ? it : it.skip

describe('POST /auth/login', () => {
  it('rechaza si faltan credenciales', async () => {
    const res = await request(app).post('/auth/login').send({})
    expect(res.status).toBe(400)  // ✓ PASS sin credenciales
  })

  itIfAuthUser('autentica con credenciales válidas', async () => {
    const res = await request(app)
      .post('/auth/login')
      .send({ email: TEST_USER_EMAIL, password: TEST_USER_PASSWORD })
    expect(res.status).toBe(200)
    expect(res.body.session?.access_token).toBeDefined()  // JWT presente
    expect(res.body.user?.id).toBeDefined()
  })
})

4.3 Prueba de acceso por rol — Admin (app-admin)

// Verifica que un usuario normal no puede acceder a rutas de admin
it('rechaza a usuario sin rol admin', async () => {

5. Cómo Ejecutar las Pruebas

5.1 Requisitos previos

# 1. Instalar dependencias
npm install

# 2. (Opcional) Configurar variables para tests autenticados
# Crear archivo .env en cada servicio:
TEST_USER_EMAIL=tu-usuario@email.com
TEST_USER_PASSWORD=tu-contraseña
TEST_ADMIN_EMAIL=admin@email.com
TEST_ADMIN_PASSWORD=contraseña-admin
SUPABASE_URL=https://xxx.supabase.co
SUPABASE_ANON_KEY=eyJ...
SUPABASE_SERVICE_ROLE_KEY=eyJ...

5.2 Comandos de ejecución

# Ejecutar todos los tests (todos los servicios en paralelo)
npm test

# Ejecutar tests de un solo servicio
cd apps/app-places && npm test

# Ejecutar con reporte de cobertura
cd apps/app-places && npx jest --coverage

# Ejecutar con reporte HTML de cobertura
cd apps/app-places && npx jest --coverage --coverageReporters=html
# Abre apps/app-places/coverage/lcov-report/index.html

# Ejecutar en modo watch (desarrollo)
cd apps/app-auth && npx jest --watch

5.3 Configuración Jest (jest.config.ts)

export default {
  preset: 'ts-jest',
  testEnvironment: 'node',
  transform: { '^.+\\.ts$': ['ts-jest', { tsconfig: 'tsconfig.json' }] },
  testMatch: ['**/__tests__/**/*.test.ts'],
  collectCoverageFrom: ['src/**/*.ts', '!src/**/*.d.ts'],
  coverageDirectory: 'coverage',
  setupFiles: ['dotenv/config'],
}
